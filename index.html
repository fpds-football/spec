FPDS Football Player Data Standard

Draft v0.1.0. Nothing here is stable, and breaking changes are expected before 1.0.

A player submission should say who claimed what.

Players are pitched between agents, intermediaries and clubs as free text with no agreed structure and no sourcing. FPDS is an open JSON format for that document — around twenty fields, and a rule that every figure carries its denominator and every claim carries its source.

The same submission with its provenance rendered. Four of these six figures came from somewhere checkable and two did not, and a recruitment analyst can see which in under a second. An interface that shows a verified minutes total and an unverified release clause in the same typeface has thrown away the point of the format.

What FPDS is not

  • Not a protocol. It defines the shape of a payload, not how two systems exchange it. A submission can travel by email, API, file drop or an attachment.
  • Not a registry. It does not tell you whether a claim is true. It tells you who made it.
  • Not a replacement for FIFA TMS. Where field names overlap, FPDS follows TMS.

Validate a submission

pip install check-jsonschema
check-jsonschema \
  --schemafile https://fpds.football/schema/v0.1/player.json \
  submission.json

Two questions the draft needs answered

Clubs and recruitment staff: what would need to be in here before you would ask agents to submit in this format?

Agents: what in this draft would stop you using it? The honest answer is more useful than the polite one.
